# hotplug-vuln-bench

Воспроизводимый стенд к статье «Уязвимости горячего подключения оперативной
памяти виртуальных машин KVM/QEMU и их экспериментальная оценка».

Стенд демонстрирует протокольные уязвимости двух механизмов горячего
подключения памяти в KVM/QEMU — модуля DIMM через ACPI и устройства
virtio-mem — на реальном коде гипервизора. Исследуется именно существующий
код KVM/QEMU; свой механизм не реализуется.

## Что показывают эксперименты

| Эксперимент | Что показывает | Скрипт |
|---|---|---|
| 1 | Извлечение модуля DIMM завершается только при размещении памяти в зоне `ZONE_MOVABLE`; при обычной зоне ядро отказывает, а QEMU молчит и не ставит тайм-аут | `experiments/exp1_dimm_unplug.py` |
| 2 | Сжатие virtio-mem — операция «по возможности»: остаток невозвращённой памяти растёт с фрагментацией гостя | `experiments/exp2_virtio_mem_frag.py` |
| 3 | Хост получает память обратно только при сговорчивом госте; без драйвера запрос молча не исполняется, а при занятой памяти свойство `size` завышает возврат памяти хосту более чем вдвое | `experiments/exp3_uncooperative.py` |

## Требования

- Linux с KVM (`/dev/kvm` доступен текущему пользователю);
- QEMU 10.x (`qemu-system-x86_64`);
- Python 3 (стандартная библиотека; для рисунков — `matplotlib`, `Pillow`);
- `gcc`, `busybox`, `zstd`, `cpio`, `gzip`, доступ к пакету ядра Ubuntu
  (`apt download linux-image-unsigned-<версия>`) для сборки гостя;
- для сборки .docx — `python-docx` (ставится в отдельное venv-окружение).

## Быстрый старт

```sh
# 1. Собрать гостевое ядро и начальный образ памяти
sh guest/build.sh                 # по умолчанию ядро 7.0.0-38-generic

# 2. Запустить эксперименты (каждый поднимает одну маленькую ВМ за раз)
python3 experiments/exp1_dimm_unplug.py --timeout 25 --repeats 3
python3 experiments/exp2_virtio_mem_frag.py --frags 0,10,20,40,80 --repeats 3
python3 experiments/exp3_uncooperative.py --modes cooperative,no_driver,busy --repeats 3

# 3. Построить рисунки (TIFF 600 dpi, чёрно-белые)
python3 figures/fig1_hotplug.py
python3 figures/fig2_weakmap.py
python3 figures/fig_exp_plots.py
```

Результаты сохраняются в `results/` (JSON и журналы трассировки QEMU),
рисунки — в `figures_out/`.

## Дисциплина памяти

Стенд рассчитан на рабочую станцию с небольшим объёмом ОП. Перед запуском
каждой ВМ проверяется доступная память хоста (`hpbench/vm.py`,
`wait_for_memory`): если её мало, запуск откладывается до освобождения.
Посторонние процессы не останавливаются. Каждая ВМ использует 256 МиБ
базовой памяти плюс окно подключения до 256 МиБ и запускается по одной.

## Структура

```
guest/        минимальный гость: init-агент, нагрузка memload.c, сборка
hpbench/      управление ВМ по QMP, драйвер хотплага, контроль памяти хоста
experiments/  три эксперимента
figures/      построение рисунков (схемы на Pillow, графики на matplotlib)
results/      выходные данные экспериментов
```

## Как это работает

Гость — дистрибутивное ядро Linux с крошечным initramfs (busybox и
статический агент), без образа диска. QEMU управляется по протоколу QMP;
включены только точки трассировки кода горячего подключения
(`mhp_*`, `memory_device_*`, `virtio_mem_*`), что изолирует в журнале
работу именно этого кода. Внутри гостя состояние блоков памяти читается
через sysfs, нагрузка создаётся непривилегированным процессом `memload`.
